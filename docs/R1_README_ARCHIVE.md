# OSMANX PROOF R1

**Первый инженерный релиз проекта PROJECT SUPERIOR:** прототип рабочей платформы, в которой пользователь покупает реальную пользу, а не право привлекать новых участников.

**Статус:** локально запускаемый прототип, НЕ production. Пять сквозных модулей в исходном коде, HTTP API, интерфейс RU/EN, 40 автоматических тестов и офлайн-визуальная проверка 7 экранов в Chromium. Реальные платежи, выплаты и отправка почты НЕ подключены.

## 1. Быстрый запуск

Требуется **Node.js 22.13 или новее**. В R1 нет внешних npm-пакетов: установка `npm install` не нужна. Используется встроенный в Node.js экспериментальный модуль `node:sqlite`.

```bash
cd osmanx-proof-r1
npm start
```

Открыть **http://127.0.0.1:3100/** и зарегистрировать тестовый аккаунт. Данные сохраняются в `./data/proof.sqlite` (создаётся автоматически).

Порядок проверки через интерфейс:

1. Регистрация (email и пароль не короче 10 символов).
2. «Создать предложение»: название, клиент, строки, цена, себестоимость, скидка; сохранить.
3. «Открыть» сохранённое предложение → «Печать / PDF» (в браузере выбрать «Сохранить в PDF») или «Поделиться» (ссылка активна 14 дней).
4. «Подписка» → «Создать счёт» → «Тестовая оплата». Это **симуляция**, фактических списаний денег нет.
5. «Партнёрство»: пользователь видит личную ссылку, но баланс начисляется только после первой подтверждённой оплаты приглашённого. Бонус удерживается 14 дней; нет выплат без реального платёжного провайдера.
6. «Поддержка»: создать обращение. «Команда»: создавать организации и приглашения.

### Windows PowerShell

```powershell
cd C:\path\to\osmanx-proof-r1
node --version
npm start
```

Открыть `http://127.0.0.1:3100`. Остановить сервер комбинацией `Ctrl+C`.

### Запуск с переменными окружения

Скопировать `.env.example` в `.env`, заменить тестовые секреты. Node.js 22 поддерживает:

```bash
node --env-file=.env src/server.mjs
```

`APP_ORIGIN` должен **в точности** совпадать с адресом сайта в браузере (с протоколом и портом). Секреты не отправлять в Git. Для тестирования по умолчанию сервер слушает только `127.0.0.1`.

### Назначить администратора

Сначала зарегистрировать обычного пользователя, затем остановить веб-сервер или использовать отдельную командную строку в том же каталоге с БД:

```bash
ADMIN_EMAIL=admin@example.com npm run init:admin
```

Для PowerShell:

```powershell
$env:ADMIN_EMAIL="admin@example.com"
npm run init:admin
```

Это CLI-действие. Веб-API не позволяет назначать себе администратора. После назначения нужно заново войти, чтобы увидеть «Контроль». В песочнице администратор может рассматривать спорные операции, вручную подтвердить возврат тестового платежа и одобрять заявку на выплату **без осуществления перевода средств**.

## 2. Проверка кода

```bash
npm run check
```

Команда делает синтаксическую проверку сервера, сервисов, БД и клиентского кода, затем запускает 40 unit/integration/HTTP-тестов. Полный отчёт: [`docs/R1_QA.md`](docs/R1_QA.md).

В `/qa/` лежат снимки **визуального mock-рендеринга** с демонстрационными значениями. Они подтверждают компоновку, не реальные финансовые показатели. В этом окружении Chromium запрещал сетевую навигацию, поэтому полноценный браузерный E2E с настоящим API не был доступен; API протестирован отдельно серверными HTTP-тестами.

## 3. Реализованные блоки

| № | Блок | Что реально работает |
|---|---|---|
| 1 | Identity & teams | Регистрация, scrypt-хэши, серверные сессии, SameSite HttpOnly-cookie, CSRF, организации, Owner/Editor/Viewer, одноразовые приглашения, RU/EN. |
| 2 | Offers & margin | CRUD коммерческих предложений, ценовые строки, скидки и налоги в копейках, статусы, лимит Free, истекающие ссылки, печать/PDF из браузера. |
| 3 | Billing sandbox | Счета с серверной ценой, проверка подписанных payment/refund events, идемпотентность, подписка Pro, отказ в завышенных возвратах, тестовая кнопка оплаты. |
| 4 | Ethical referrals | Опциональная ссылка, разовая скидка, бонус за первую оплату, лимит по доступной марже, 14-дневный hold, отмена при возврате, учёт обязательств. |
| 5 | Audit & trust | SHA-256 hash-chain аудита, двойные проводки, сигналы shared-network, заявки на выплаты, отзывы администратора, обращения. |

## 4. Что НЕ реализовано в R1

- **Нет Next.js/TypeScript/PostgreSQL**, хотя это целевая архитектура. Сейчас Node.js, ES modules и SQLite для воспроизводимого запуска без сторонних зависимостей. Переход описан в `docs/ARCHITECTURE.md`.
- **Нет настоящего эквайринга и payouts.** `PAYMENT_MODE=sandbox` разрешён только вне production. `bridge` принимает исключительно внутренние HMAC-события от отдельного доверенного адаптера (сам адаптер реального эквайринга пока не создан).
- Нет email-подтверждения адреса, автоматического сброса пароля, приглашений по email, KYC, криптографической подписи внешних выписок, многоузлового лимитирования, полноценной локализации клиентских документов, политик удаления и юридических договоров.
- Нет нативных iOS/Android приложений; текущая мобильная версия — адаптивный веб-интерфейс.
- Не выполнено полноценное браузерное E2E с backend на реальных браузерных сетевых запросах, нагрузочное и независимое пен-тестирование.

**Размещать текущий R1 в открытом Интернете, принимать деньги или обещать выплаты нельзя.** В `docs/SECURITY.md` есть перечень блокирующих работ перед публикацией.

## 5. Структура

```
osmanx-proof-r1/
  src/db.mjs             Драйвер и миграции SQLite
  src/security.mjs       Сессии, scrypt, HMAC, проверки
  src/finance.mjs        Денежные расчёты и лимиты
  src/services.mjs       Бизнес-операции в транзакциях
  src/server.mjs         HTTP API и статический SPA
  src/admin-cli.mjs      Ручное назначение администратора
  db/schema.sql          Транзакционная схема данных
  public/index.html      Web shell
  public/styles.css      Премиальный адаптивный дизайн
  public/app.js          Реальные пользовательские сценарии
  public/print.*         Печатная версия коммерческого предложения
  tests/*.test.mjs       40 автоматических тестов
  qa/                    Visual QA (mock screenshots) и скрипты
  docs/                  API, архитектура, финансы, QA, безопасность
  .github/workflows/     CI для проверки после переноса в GitHub
```
